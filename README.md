# DNA Biosensor Design and Success-Prediction Tool

A Python project for generating candidate DNA biosensor arm designs from an analyte sequence, calculating thermodynamic features, and ranking candidates with a machine-learning model.

The repository contains two connected parts:

1. A **data-preparation and model-training pipeline** that converts experimental biosensor data into ML-ready features and trains classification models.
2. A **command-line design tool** that accepts a DNA analyte sequence in FASTA format, generates candidate sensor arms, filters them, scores them with the trained model, and writes a report with the best candidates.

## Part 1: Model-development pipeline

The training pipeline transforms historical biosensor experiments into numerical features and learns to classify whether an experimental design is successful.

### Pipeline overview

```text
raw_data.csv
    |
    v
data_prep.py
    |
    |-- Removes reference-only fields
    |-- One-hot encodes sensor, core, and analyte categories
    |-- Converts DNA sequence columns into Gibbs free-energy values
    |-- Creates a binary success label
    v
data.csv
    |
    +--> rf_training.py  --> rf_model.joblib + rf_metrics.txt
    |
    +--> hgb_training.py --> hgb_model.joblib + hgb_metrics.txt
```

### 1. Prepare experimental data

Run:

```bash
cd src
python data_prep.py
```

`data_prep.py` reads `data/raw_data.csv` and writes the processed dataset to `data/data.csv`.

The preprocessing step:

- Removes `results_ref` and `sensor_ref`, which are reference fields rather than predictive experimental measurements.
- One-hot encodes categorical columns whose names contain `type_`, producing binary model features for sensor, core, and analyte types.
- Removes concentration and incubation fields that are considered fully determined by the sensor, core, or analyte type in the current dataset.
- Normalizes visually similar Cyrillic DNA characters (`А`, `С`, `Т`) to Latin characters (`A`, `C`, `T`) before sequence processing.
- Replaces sequence-valued columns with Gibbs free-energy (\(\Delta G\)) values calculated using `seqfold.dg()` at each experiment’s recorded temperature.
- Calculates the ratio:

\[
\text{success} = \frac{\text{ctrl\_pos}}{\text{ctrl\_neg}}
\]

- Creates the binary target column `class_2`, where:

```text
class_2 = 1  if success > 2
class_2 = 0  otherwise
```

- Removes `success`, `ctrl_pos`, and `ctrl_neg` after the target label is created, preventing those outcome measurements from entering the model as features.

### 2. Train the models

After `data/data.csv` has been generated, run either or both training scripts from the `src/` directory.

Train the Random Forest model:

```bash
python rf_training.py
```

Train the Histogram Gradient Boosting model:

```bash
python hgb_training.py
```

Both scripts:

- Read `data/data.csv`.
- Remove `temp_C`.
- Rename processed sequence-feature columns from `*_seq` to `*_dg`.
- Use `class_2` as the binary target variable.
- Replace infinite numerical values with missing values (`NaN`).
- Split data into 80% training and 20% test sets with `random_state=100`.
- Run five-fold cross-validation on the training set.
- Fit the final model on the full training split.
- Evaluate accuracy and produce a classification report on the held-out test set.
- Calculate permutation feature importance using 50 repeats.
- Save the fitted model and a text report in `models/`.

### Model outputs

| Script | Algorithm | Saved model | Evaluation report |
|---|---|---|---|
| `rf_training.py` | `RandomForestClassifier`, 250 trees | `models/rf_model.joblib` | `models/rf_metrics.txt` |
| `hgb_training.py` | `HistGradientBoostingClassifier`, maximum 250 iterations | `models/hgb_model.joblib` | `models/hgb_metrics.txt` |

The current design tool loads `models/hgb_model.joblib`. You should inspect both metrics files and choose the model based on validation performance, class-level precision/recall, and scientific plausibility of important features—not accuracy alone.

## Part 2: Biosensor-design tool

`src/main.py` is a command-line program that generates and ranks candidate DNA biosensor designs for an input analyte sequence.

It currently scores designs with the trained Histogram Gradient Boosting model.

### What the tool does

The tool performs the following steps:

1. Reads the analyte DNA sequence from a single-record FASTA file.
2. Optionally identifies an amplified region using forward and backward primers.
3. Generates reverse-complement target windows from the analyte sequence.
4. Builds two-, three-, or four-arm candidates according to the selected sensor architecture.
5. Filters arms by length, GC content, melting temperature, uniqueness, and optional cross-complementarity screening.
6. Adds architecture-specific constant sequences to each arm.
7. Calculates Gibbs free energy (\(\Delta G\)) for modified arms.
8. Keeps the 100 candidates with the lowest summed arm \(\Delta G\).
9. Uses the trained HGB classifier to calculate a predicted probability for class `1`.
10. Writes a timestamped report containing the three highest-ranked candidate designs.

### Sensor architectures

Choose exactly one sensor type:

| Option | Short form | Description | Number of arms |
|---|---|---|---|
| `--dnazyme_binary` | `-bidz` | Binary DNAzyme sensor | 2 |
| `--dnazyme_dnm` | `-dnm` | DNM DNAzyme sensor | 3 |
| `--g_quadruplex` | `-g4` | G-quadruplex sensor | 4 |

### Analyte types

Choose exactly one analyte type:

| Option | Short form | Description |
|---|---|---|
| `--dsDNA` | `-ds` | Double-stranded DNA analyte |
| `--ssDNA` | `-ss` | Single-stranded DNA analyte |
| `--amplicon` | `-ampl` | PCR-amplified analyte region |

### Input FASTA format

The analyte file must contain a header beginning with `>` followed by one DNA sequence containing only `A`, `T`, `G`, and `C`.

Example, `analyte.fasta`:

```fasta
>example_analyte
ATGCATGCATGCATGCATGCATGCATGCATGCATGCATGCATGCATGCATGC
```

### Basic usage

Run the command from the `src/` directory because the current scripts use relative paths to `../data/` and `../models/`.

```bash
cd src
python main.py ../examples/analyte.fasta --dnazyme_binary --dsDNA
```

Example: generate DNM DNAzyme candidates for an amplicon:

```bash
python main.py ../examples/analyte.fasta \
  --dnazyme_dnm \
  --amplicon \
  --window_length 100 \
  --output ../outputs
```

Example: generate G-quadruplex candidates and screen their arms against an additional sequence:

```bash
python main.py ../examples/analyte.fasta \
  --g_quadruplex \
  --ssDNA \
  --compare_fastafile ../examples/off_target.fasta \
  --output ../outputs
```

Example: limit the analyte to a primer-defined amplification region:

```bash
python main.py ../examples/analyte.fasta \
  --dnazyme_binary \
  --amplicon \
  --primers ../examples/primers.txt \
  --output ../outputs
```

### Command-line options

```text
usage: main.py [-h]
               [--window_length WINDOW_LENGTH]
               (--dnazyme_binary | --dnazyme_dnm | --g_quadruplex)
               (--dsDNA | --ssDNA | --amplicon)
               [--compare_fastafile COMPARE_FASTAFILE]
               [--primers PRIMERS]
               [--output OUTPUT]
               analyte_fastafile
```

| Argument | Short form | Required | Description |
|---|---|---:|---|
| `analyte_fastafile` | — | Yes | Path to the analyte FASTA file |
| `--window_length` | `-wl` | No | Desired target-window length; default: 100 bases |
| `--dnazyme_binary` | `-bidz` | One sensor type is required | Selects a two-arm binary DNAzyme architecture |
| `--dnazyme_dnm` | `-dnm` | One sensor type is required | Selects a three-arm DNM DNAzyme architecture |
| `--g_quadruplex` | `-g4` | One sensor type is required | Selects a four-arm G-quadruplex architecture |
| `--dsDNA` | `-ds` | One analyte type is required | Marks the analyte as double-stranded DNA |
| `--ssDNA` | `-ss` | One analyte type is required | Marks the analyte as single-stranded DNA |
| `--amplicon` | `-ampl` | One analyte type is required | Marks the analyte as an amplicon |
| `--compare_fastafile` | `-c` | No | FASTA sequence used for cross-complementarity screening |
| `--primers` | `-p` | No | Text file containing forward and backward primers |
| `--output` | `-o` | No | Directory for the generated report; default: current directory |

### Primer-file format

Provide two lines in this exact format:

```text
F0: ATGCATGCATGCATGCATGC
B0: CGTACGTACGTACGTACGTA
```

The program reverse-complements the `B0` primer before searching for it in the analyte sequence.

### Output report

The tool creates a timestamped `.txt` file. Its name includes the input FASTA name, selected sensor type, analyte type, and run timestamp.

A report includes:

- Input-analyte name and selected analyte type.
- Chosen sensor architecture.
- Header of the optional comparison sequence.
- The three highest-ranked candidate designs.
- The model’s predicted class-1 probability for each candidate.
- Candidate target and unmodified arm sequences.
- Modified arm sequences.
- Per-arm Gibbs free energy values and summed \(\Delta G\).

## Important implementation notes

- The model expects the same input-feature schema used during training. If you change preprocessing, sensor architectures, modification sequences, or engineered features, retrain the model before using it for new predictions.
- `main.py` currently loads the Histogram Gradient Boosting model from `../models/hgb_model.joblib`.
- Candidate filtering uses arm lengths of 18–26 nucleotides, GC content from 40% to 60%, and melting temperature from 52°C to 65°C.
- The tool uses temperatures of 55°C for DNAzyme architectures and 23°C for the G-quadruplex architecture when calculating \(\Delta G\).
- The current code generates candidate arms from reverse-complemented target sequences.
- The current implementation should be run from `src/` because several scripts use paths relative to the working directory.
- The candidate window length should be compatible with the architecture. In particular, a four-arm design requires a minimum total arm length of 72 bases.

## Limitations

- This is a candidate-generation and ranking system, not a complete in-silico validation workflow.
- A classifier’s probability is not a direct measurement of experimental success probability or assay sensitivity.
- The current off-target check is based on exact sequence occurrence and does not replace full alignment-based specificity analysis.
- The current evaluation procedure uses a random train/test split and K-fold cross-validation; datasets with related experiments may require group-aware validation to avoid information leakage.
- Thermodynamic calculations depend on the assumptions and conditions implemented by the underlying `seqfold` library.
- All high-ranking designs require wet-lab validation.
